# AI support and private photos

Customer support opens at `/orders/[id]/support`. A new conversation starts with the AI assistant when `GROQ_API_KEY` is configured in the server environment. `GROQ_SUPPORT_MODEL` defaults to `llama-3.1-8b-instant` and can be changed to a Groq chat-completions model available to your account that supports JSON object mode. Restart local development or redeploy after setting environment values. Keep the API key server-only; do not add a `NEXT_PUBLIC_` prefix.

The implementation uses [Groq Chat Completions](https://console.groq.com/docs/api-reference) and [JSON object mode](https://console.groq.com/docs/structured-outputs), with a 15-second timeout and a maximum of three AI replies before the next unresolved message is handed to an agent. Groq only classifies the latest message into an allowlisted UCALL support intent. The server renders approved support-only responses using whitelisted order status and payment fields. Raw model prose, arbitrary extra fields and unknown intents are never displayed. Unrelated requests receive a fixed UCALL-only refusal. Even if a prompt injection produces a valid intent, the available output is limited to approved UCALL support templates.

The request sends the recent text conversation and minimal order facts, excluding stored shipping address, phone, email, payment identifiers, product names, tracking text and photo bytes. Customers should not put sensitive payment details in chat. AI replies are identified as AI in the conversation. The default model’s documented JSON mode is described in [Groq’s Llama 3.1 8B reference](https://console.groq.com/docs/model/llama-3.1-8b-instant); availability depends on your Groq account.

Customers can choose **Chat to agent** at any time. Explicit unresolved/agent requests and photo submissions are handed to the human inbox. The AI also classifies issues that need human action. It cannot approve refunds, change orders or prioritise delivery; those operations use the existing authenticated workflows. Provider failures, malformed answers, refusals or missing API configuration create a clear handoff instead of a simulated AI reply. Admin replies take over immediately and prevent any pending AI answer from being posted. All history is retained for the agent.

Chat accepts up to three photos per message, including a photo without text. Accepted uploads are JPG, PNG, WebP and AVIF, up to 4 MiB each. The server decodes and re-encodes each photo as JPEG, strips metadata, bounds its dimensions and compresses it to at most 350 KiB. Animated, malformed and oversized files are rejected. The private photo data is stored in a server-only Firestore subcollection, so the feature does not require Firebase Storage. Downloads require a current signed-in owner or the sole authorized admin; image URLs are not public. Client Firestore access remains denied by the existing default rule. Uploads are limited per user and to 100 distinct photos per conversation.

Deploy the updated app and set `GROQ_API_KEY` in the hosting environment to enable live AI intent classification. The checked-in example has no key. Automated tests stub the provider and do not spend API credits.
